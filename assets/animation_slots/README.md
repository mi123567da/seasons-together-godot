# 主角位图动画交付规范

此目录只预留动画资源槽，不包含生成图片。美术请按外观与武器分别交付：`female` / `male` × `bow` / `sword` / `staff` / `spirit_focus`。每组下设 `idle`、`run`、`basic`、`q`、`e`、`r`、`dash`、`hurt` 八个动作目录。目录已经创建，可直接将透明 PNG 放入对应位置。

## 文件路径与命名

```text
{外观}/{武器}/{动作}/{方向}_{帧号两位}.png
female/bow/idle/S_00.png
female/bow/idle/S_01.png
female/bow/run/SE_00.png
male/spirit_focus/q/NE_00.png
```

- 帧号从 `00` 开始。方向名使用大写 `N`、`NE`、`E`、`SE`、`S`。
- 每个动作只绘制五套朝向：北、东北、东、东南、南。西向使用东向水平镜像，西北使用东北向镜像，西南使用东南向镜像；不要为这三向另交文件。
- 每个动作的所有帧都必须交齐。程序只在某方向整套帧完整时播放位图动画，否则该方向整段使用现有立绘，避免空缺帧和静态立绘交替闪烁。

## 画布与锚点

- 每帧使用 `256 × 256` 像素、RGBA 真透明 PNG。不要用白底、纯色底或半透明底代替透明区域。
- 所有帧共用同一画布和比例。角色脚底落在画布底边中央，锚点是归一化坐标 `(0.5, 1.0)`，对应像素约 `(128, 256)`。
- 保持头顶、武器、衣摆和特效都在画布内；动作帧只改变身体姿势，脚底锚点和角色整体占位不要跳动。
- 水平镜像会反转角色与道具方向。请避免必须左右辨认的文字或不对称标记；如某武器造型无法镜像，应先与程序侧确认方向方案。

## 动作帧与播放

| 动作目录 | 最少帧数 | 帧率 | 播放方式 |
| --- | ---: | ---: | --- |
| `idle` | 4 | 6 fps | 循环 |
| `run` | 5 | 10 fps | 循环 |
| `basic` | 5 | 12 fps | 单次 |
| `q` / `e` / `r` | 每项 5 | 12 fps | 单次 |
| `dash` | 5 | 12 fps | 单次 |
| `hurt` | 5 | 8 fps | 单次 |

`idle` 与 `run` 应首尾衔接。攻击、技能、闪避和受击动作按帧号顺序播放一次；完成后由游戏状态切回待机或移动。每个外观/武器组合共需 39 帧 × 5 个原画方向；全部 8 个组合完整时为 1,560 张 PNG。

## 程序读取与缺图回退

`scripts/bitmap_animation_catalog.gd` 的 `BitmapAnimationCatalog` 提供静态读取 API。`expected_frame_path(...)` 可在文件尚未交付时生成预期路径用于清单；`get_frame_path(...)` 和 `load_frame(...)` 对缺图返回 `null`。动画目录应先通过 `has_complete_direction(...)` 检查整段帧是否齐全；`load_frame_or_fallback(...)` 会自动执行该检查，并在缺图时返回调用方传入的现有立绘。

方向映射 API 会返回源方向和 `flip_h`。加载文件只用 `ResourceLoader`，兼容导出后的 PCK。导入新一批图片后，如编辑器仍在运行，可调用 `clear_cache()` 让本次会话重新检查槽位。
